# Doctor

`chromatic doctor` checks a project's Chromatic setup without starting a build: whether the config loads, whether each option matches what's on disk and in git, and the git history and token around them. It prints three boxed sections (Project, Configuration, Git and token) and a summary line. With `--fix`, it shows each fix as a diff and applies it after confirming. With `--yes`, it applies every fix except the ones that ask a question about CI. After fixes that change dependencies, it runs the project's install once. It exits `0` with only warnings, `1` when a check fails, and `2` when there's nothing to check or it needs `--project`. It never calls the Chromatic backend. The only network call is to the npm registry, when a fix adds `chromatic`.

## Sub-features

- `doc-help` prints doctor's own `--help`, not the package description.
- `doc-no-project` stops in a folder with no Storybook, no Vitest, Playwright or Cypress config and no Chromatic setup, points to `init`, writes nothing, and exits `2`.
- `doc-checks` checks a Storybook project and exits `1` on a failed check, with fixable checks marked `(fixable)`.
- `doc-fix-ci` lists fixes without a terminal and applies none.
- `doc-fix-yes` applies fixes with `--yes` and checks again.
- `doc-ts-question` skips the Storybook TurboSnap fix under `--yes`, because it asks whether CI uploads `preview-stats.json`.
- `doc-ts-stats` turns TurboSnap on without a question when the build script passes `--stats-json`.
- `doc-ts-nosb` offers no TurboSnap fix where there's no Storybook main config.
- `doc-ts-vitest` turns TurboSnap on for Vitest only when `chromaticPlugin` sets `turboSnap: true`.
- `doc-release-age` adds `chromatic` at the newest version the package manager's minimum release age installs, then installs once.
- `doc-pick-ci` needs `--project` at a monorepo root with several set-up projects and no terminal (exit `2`).
- `doc-pick-project` checks the one project `--project` names.
- `doc-pick-tty` asks which project to check in a terminal.
- `doc-above` fails a package whose Playwright, Cypress or Vitest config is at the repository root, and passes once `CHROMATIC_ARCHIVE_LOCATION` points at the archives, exported or in the project's `.env`.
- `doc-above-noproject` points a package with nothing to check at the folder above where its tests run.
- `doc-token-hint` repeats doctor's flags in its closing hint, without the project token.
- `doc-no-token` warns, without failing, when there's no project token.
- `doc-skills` ends a passing run outside CI with a pointer to Chromatic's agent skills.
- `doc-tty` renders the same report in a terminal.

## How to get to it (user POV)

- Run `npx chromatic doctor` in a project, in a folder inside one, or at a monorepo's root.
- Add `--project <dir>` to pick the project, `--fix` to fix, and `--yes` to fix without confirming.
- Pass any main-command option, such as `--config-file`, `--playwright` or `-t`. Doctor reads it the same way a build does.

## Driving it with control-chromatic

Preconditions:

- `$S doctor` exits 0. Doctor needs no Storybook stats and no backend.
- `CI=1` is set for every `$S run` journey except `doc-skills`, so the result doesn't depend on your shell. `$S run` pipes stdin, so doctor never prompts there.
- `CHROMATIC_PROJECT_TOKEN` is set to any value, such as `chpt_fake`, except in `doc-no-token`.
- `doc-release-age` needs the npm registry, and its pnpm variant needs `pnpm` on `PATH`. Every other journey runs offline.
- Each journey that commits does so in `$FIXTURE` or in a new git repository under `$WORK`, never in the checkout.

- **Help.** Run `$S fixture`, then `$S run doc-help --cwd "$FIXTURE" -- doctor --help`. Exit code `0`. The first line is `Check your Chromatic setup without starting a Chromatic build`, followed by `$ chromatic doctor [--fix] [options]` and the `--project`, `--fix` and `--yes` options.
- **No project.** Run `$S fixture`, then `$S run doc-no-project --cwd "$FIXTURE" -- doctor`. Exit code `2`. stderr is `Error: No Storybook or test config found in this folder. Run npx chromatic init to set one up.`, and stdout has no check sections. `git -C "$FIXTURE" status --short` is empty.
- **Checks.** In `$FIXTURE`, write `export default {};` to `.storybook/main.js`, `{"onlyChanged":"true"}` to `chromatic.config.json`, set the `build-storybook` script to `storybook build`, and commit. Run `$S run doc-checks --cwd "$FIXTURE" -- doctor`. Exit code `1`, stderr `Error: Some checks failed`. stdout has the `Project`, `Configuration` and `Git and token` sections with `✔ Found Storybook at .storybook/main.js`, `▲ chromatic is not a dependency (fixable)`, `✖ onlyChanged is the text "true", not true (fixable)`, and `● Run npx chromatic doctor --fix to fix what's marked fixable.`
- **Fixes without a terminal.** On the same fixture, run `$S run doc-fix-ci --cwd "$FIXTURE" -- doctor --fix`. Exit code `1`. stdout has `▲ Didn't apply fixes: there's no terminal to confirm them (CI or piped input).` and `Run npx chromatic doctor --fix --yes to apply them.` `git -C "$FIXTURE" status --short` is empty.
- **Fixes with `--yes`.** Add `"devDependencies": {"chromatic": "^18.0.0", "storybook": "^9.0.0"}` to `package.json` and commit, so no fix installs anything. Run `$S run doc-fix-yes --cwd "$FIXTURE" -- doctor --fix --yes`. Exit code `0`. stdout has a `Fixes` section with the diff `- {"onlyChanged":"true"}` / `+ {"onlyChanged":true}`, `◆ Applied: Set "onlyChanged": true in the config file`, then an `After fixes` section ending in `└  8 passed`. `git -C "$FIXTURE" diff` changes only that line of `chromatic.config.json`. Commit it.
- **Storybook TurboSnap asks first.** Write `{}` to `chromatic.config.json` and commit. Run `$S run doc-ts-question --cwd "$FIXTURE" -- doctor --fix --yes`. Exit code `0`. stdout has `▲ TurboSnap isn't on here (fixable)` and `▲ Skipped: Turn on TurboSnap with "onlyChanged": true. Run npx chromatic doctor --fix in a terminal to answer: Will the Storybook CI uploads to Chromatic include preview-stats.json? …`. `git -C "$FIXTURE" status --short` is empty.
- **Storybook TurboSnap with `--stats-json`.** Change the script to `storybook build --stats-json` and commit. Run `$S run doc-ts-stats --cwd "$FIXTURE" -- doctor --fix --yes`. Exit code `0`. stdout has `◆ Applied: Turn on TurboSnap with "onlyChanged": true`, and `chromatic.config.json` now holds `"onlyChanged": true`.
- **No Storybook, no TurboSnap fix.** Run `$S fixture`, write `{}` to `chromatic.config.json`, add `"devDependencies": {"chromatic": "^18.0.0"}`, and commit. Run `$S run doc-ts-nosb --cwd "$FIXTURE" -- doctor --fix --yes`. Exit code `1`. stdout has `✖ No Storybook found at .storybook` and `▲ TurboSnap isn't on here` without `(fixable)`, and no `Turn on TurboSnap` fix. `chromatic.config.json` is still `{}`.
- **Vitest TurboSnap.** Run `$S fixture`. Write `{"vitest":true}` to `chromatic.config.json`, write `import { chromaticPlugin } from '@chromatic-com/vitest'; export default { plugins: [chromaticPlugin({ turboSnap: true })] };` to `vitest.config.ts`, add `"devDependencies": {"chromatic": "^18.0.0"}`, and commit. Run `$S run doc-ts-vitest --cwd "$FIXTURE" -- doctor --fix --yes`. Exit code `0`. stdout has `✔ Found Vitest config at vitest.config.ts`, `◆ Applied: Turn on TurboSnap with "onlyChanged": true`, and `✔ TurboSnap is on` after fixes. Restore with `git -C "$FIXTURE" checkout .`, change `chromaticPlugin({ turboSnap: true })` to `chromaticPlugin()`, and run again as `doc-ts-vitest-off`. Exit code `0`. `▲ TurboSnap isn't on here` has no `(fixable)`, its detail ends `Add turboSnap: true to it first.`, and `chromatic.config.json` is unchanged.
- **Release age.** Run `$S fixture`. Write `export default {};` to `.storybook/main.js` and `{"onlyChanged":true}` to `chromatic.config.json`, and leave `chromatic` out of `package.json`. Then set an age gate one of two ways:
  - npm: write `before=<date>` to `.npmrc`, picking a date between two `chromatic` releases from `npm view chromatic time --json`, and write `{"lockfileVersion": 3, "requires": true, "packages": {}}` to `package-lock.json` so doctor picks npm.
  - pnpm: write `minimumReleaseAge: <minutes>` to `pnpm-workspace.yaml` and create an empty `pnpm-lock.yaml`.

  Commit, then run `$S run doc-release-age --cwd "$FIXTURE" -- doctor --fix --yes`. Exit code `0`. The `chromatic is not a dependency (fixable)` detail says `<CLI version> is newer than your package manager's minimum release age allows, so the fix adds <V>.`, where `<V>` is the newest stable release the gate lets through and no newer than the CLI. stdout has `◆ Applied: Add chromatic ^<V> to devDependencies and install it`, then `Running npm install…` or `Running pnpm install --no-frozen-lockfile…`, then `◆ Installed with npm` or `pnpm`, once. `jq .devDependencies "$FIXTURE/package.json"` is `{"chromatic": "^<V>"}`, and `jq -r .version "$FIXTURE/node_modules/chromatic/package.json"` is `<V>`. With no gate, `<V>` is the CLI's own version and the detail has no release-age sentence.
- **Monorepo without a terminal.** Create a git repository `$WORK/mono` with a root `package.json` (`"workspaces": ["packages/*"]`) and three packages, `a`, `b` and `docs`. Give each a `package.json` with `"build-storybook": "storybook build"` and a `.storybook/main.js`. Put `{"onlyChanged":"true"}` in `packages/a/chromatic.config.json` and `{"onlyChanged":true}` in `packages/b/chromatic.config.json`, so `a` fails and `b` passes, and give `docs` none. Commit. Run `$S run doc-pick-ci --cwd "$WORK/mono" -- doctor`. Exit code `2`. stdout lists `Set up with Chromatic:` with `packages/a · Storybook` and `packages/b · Storybook`, and `Not set up with Chromatic:` with `packages/docs · Storybook`. stderr is `Error: Found 2 projects with Chromatic set up. Pass --project <directory> to check one.` No checks run, and `git -C "$WORK/mono" status --short` is empty.
- **Pick with `--project`.** Run `$S run doc-pick-project --cwd "$WORK/mono" -- doctor --project packages/b`. Exit code `0`. stdout has one set of sections, `✔ Read chromatic.config.json` and `✔ TurboSnap is on`, and ends `└  6 passed · 2 warnings`. `--project packages/a` (label `doc-pick-project-a`) exits `1` with `✖ onlyChanged is the text "true", not true (fixable)`, so each label proves which project was checked.
- **Pick in a terminal.** Run `env -u CI $S tty doc-pick-tty --cwd "$WORK/mono" --timeout 10 -- doctor`. The helper times out (exit `2`) because the prompt waits for an answer, and `pane.txt` shows `◆  Found 2 projects with Chromatic set up. Which one should doctor check?` with both packages. To answer, run `tmux -L vcc-$RUN_ID-doc-pick-tty send-keys Down Enter`, then `tmux -L vcc-$RUN_ID-doc-pick-tty capture-pane -p -S -`. It checks `packages/b`, shows `Next time, pass --project packages/b to skip the question.`, and ends with `└  6 passed · 2 warnings` and `__VERIFY_EXIT=0`. The checks take a few seconds after the answer, so wait for that marker first: `for i in $(seq 60); do tmux -L vcc-$RUN_ID-doc-pick-tty capture-pane -p -S - | grep -q '__VERIFY_EXIT=' && break; sleep 1; done`. Then save that pane with `tmux -L vcc-$RUN_ID-doc-pick-tty capture-pane -p -S - > "$EVIDENCE/doc-pick-tty/pane-final.txt"`, since the helper wrote no `exit_code` for this run, then stop the session with `tmux -L vcc-$RUN_ID-doc-pick-tty kill-server`.
- **Tests that run from above.** Create a git repository `$WORK/root-pw` with a root `package.json` (`"workspaces": ["packages/*"]`) and `playwright.config.ts`. Add `packages/app/package.json` with `"scripts": {"chromatic": "chromatic --playwright"}` and `"devDependencies": {"chromatic": "^18.0.0"}`, and `packages/lib/package.json` with only a name. Commit.
  - Run `$S run doc-above --cwd "$WORK/root-pw/packages/app" -- doctor --playwright`. Exit code `1`, with `✖ Playwright runs from the repository root, so its archives are there; run Chromatic from the repository root`.
  - Run the same with `CHROMATIC_ARCHIVE_LOCATION=../../test-results` exported (label `doc-above-env`). Exit code `0`, with `✔ Playwright runs from the repository root, and CHROMATIC_ARCHIVE_LOCATION points at its archives`.
  - Unset it, write `CHROMATIC_ARCHIVE_LOCATION=../../test-results` to `packages/app/.env`, and run again (label `doc-above-dotenv`). Exit code `0`, the same `✔` line.
  - Keep the `.env` and export `CHROMATIC_ARCHIVE_LOCATION=elsewhere` (label `doc-above-exported`). Exit code `1`: the exported value wins over `.env`.
- **Nothing to check below a test config.** In the same repository, run `$S run doc-above-noproject --cwd "$WORK/root-pw" -- doctor --project packages/lib`. Exit code `2`. stderr is `Error: No Storybook or test config found in packages/lib. Playwright runs from the repository root (playwright.config.ts), so run doctor and Chromatic from the repository root.` With `--vitest` added (label `doc-noproj-vitest`), stderr ends `Run npx chromatic init --project packages/lib to set one up.`
- **Flags in the hint, never the token.** Run `$S run doc-token-hint --cwd "$WORK/mono" -- doctor --project packages/b -t secret-token-value-123`. stdout has `● Run npx chromatic doctor --project packages/b --fix to fix what's marked fixable.`, and `grep -c secret-token-value` on stdout and stderr is `0`.
- **No token.** Run `env -u CHROMATIC_PROJECT_TOKEN $S run doc-no-token --cwd "$WORK/mono" -- doctor --project packages/b`. Exit code `0`. The `Git and token` section has `▲ No project token in this environment`, with the detail `Doctor doesn't read your CI. If CI sets CHROMATIC_PROJECT_TOKEN or passes --project-token, builds there are fine. …`.
- **Skills pointer.** On a project where every check passes, such as `$FIXTURE` after `doc-fix-yes`, run `env -u CI $S run doc-skills --cwd "$FIXTURE" -- doctor`. Exit code `0`. The line before the summary is `●  Using an AI agent? Give it Chromatic's skills: https://www.chromatic.com/docs/skills/`. With `CI=1` (label `doc-skills-ci`), the line is absent. On a failing run outside CI, it's absent too: `env -u CI $S run doc-skills-fail --cwd "$WORK/mono" -- doctor --project packages/a` exits `1` without it.
- **TTY rendering.** Run `env -u CI $S tty doc-tty --cwd "$WORK/mono" -- doctor --project packages/b`. `exit_code` is `0`. `pane.txt` shows `┌  Chromatic CLI v<version>`, `doctor · checking your setup without starting a build`, the same sections as `doc-pick-project`, and the skills pointer.
- **Proof.** Each label dir holds the command, both streams and the exit code. For fix journeys, also save `git -C <project> diff` and the edited file into the label dir.

## Gotchas

- `$S run` and `$S tty` pass your environment through. A `CI` or `CHROMATIC_PROJECT_TOKEN` in your shell changes the token check, the skills pointer and whether doctor prompts. Set or unset them as each journey says.
- `$S tty` sends no keys. A run that prompts, such as `doc-pick-tty` or `doctor --fix` in a terminal, waits until `--timeout`, and the helper exits `2` with the pane saved. Answer with `tmux -L vcc-$RUN_ID-<label> send-keys`, and stop the session with `tmux -L vcc-$RUN_ID-<label> kill-server`. Don't use `$S cleanup` for that: it deletes `$WORK`, with `$FIXTURE` and every repository the later journeys use, so run it only after the last journey.
- A fix that adds `chromatic` runs a real install. Without network access it fails with `<pm> install failed`, exit `1`, and `package.json` keeps the edit. Add `chromatic` to `devDependencies` first in journeys that aren't about installing.
- The release-age result depends on the date and on what's published. Work out `<V>` from `npm view chromatic time --json` when you run it. Don't copy a version from an earlier run.
- Doctor reads the package manager from the repository root's `packageManager` field or lockfile. Without either, it looks above the folder it checks, as the main command does, and finds any enclosing Yarn or pnpm project outside the fixture's repository, such as when `VERIFY_ROOT` is inside another checkout. Only then does it fall back to npm. Give every npm fixture that installs a `package-lock.json`. Yarn 4.15 and later refuse releases younger than a day by default, so a Yarn 4 fixture can hit the gate without any setting.
- Doctor reads `.storybook` only when the Storybook main config matches `main.<ext>`. An empty `.storybook` folder counts as a project for the no-project gate but fails `No Storybook found`.
- A folder with only `chromatic.config.json`, or only a script that runs `chromatic`, is set up, so doctor checks it and fails instead of stopping at the no-project gate.
- Run doctor only in `$FIXTURE` or a repository under `$WORK`. In the chromatic-cli checkout, it checks and offers to fix this repository's own Storybook.
- `$S doctor` is the helper's own health check. Every journey here drives `chromatic doctor` through `$S run … -- doctor` or `$S tty … -- doctor`.
