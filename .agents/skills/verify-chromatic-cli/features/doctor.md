# Doctor

`chromatic doctor` checks a project's Chromatic setup without starting a Chromatic build: whether the config loads, whether each option matches what's on disk and in git, and the git history and token around them. It prints three boxed sections (Project, Configuration, Git and token) and a summary line. With `--fix`, it shows each fix as a diff and applies it after confirming. With `--yes`, it applies every fix except the ones that ask a question, such as whether CI uploads `preview-stats.json`, whether to update `chromatic` to a new major version, or whether Storybook reads the files doctor offers to add to `externals`. Each fixable item names the ID of its fix, and `--apply <id>` applies that fix, answering yes to its question; every skipped question comes with the `--apply` command that answers it. After fixes that change dependencies, it runs the project's install once. It exits `0` with only warnings, `1` when a check fails, and `2` when there's nothing to check, it needs `--project`, or an `--apply` names no fix the project offers. When package.json lists `chromatic`, the Project section also says which version is installed and how far behind the latest release it is, and `--fix` offers to update it. It never calls the Chromatic backend. Its only network calls are to the npm registry: the latest-release lookup, which becomes an info line when the registry can't be reached, and the install after a fix that adds or updates `chromatic`. With TurboSnap on for the current branch in a Storybook project, it first builds Storybook with stats into a temporary folder, as a TurboSnap build does, and shows what the Storybook preview reaches: with TurboSnap, a change to any of those files recaptures every story. From the same stats file, it lists the project's stylesheets, images and fonts that TurboSnap can't see, and `--fix` offers to add them to `externals`.

## Sub-features

- `doc-help` prints doctor's own `--help`, not the package description.
- `doc-no-project` stops in a folder with no Storybook, no Vitest, Playwright or Cypress config and no Chromatic setup, points to `init`, writes nothing, and exits `2`.
- `doc-config-file` fails a check, rather than stopping with `ENOTDIR`, when the build script's `-c` names a file, relative or absolute.
- `doc-config-dir-file` fails `storybookConfigDir` once, with the option values, when it names a file.
- `doc-checks` checks a Storybook project and exits `1` on a failed check, with fixable checks marked `(fixable: <id>)`.
- `doc-fix-ci` lists fixes without a terminal and applies none.
- `doc-fix-yes` applies fixes with `--yes` and checks again.
- `doc-ts-question` skips the Storybook TurboSnap fix under `--yes`, because it asks whether CI uploads `preview-stats.json`, and prints the `--apply` command that answers it. Without `--yes`, `doc-ts-question-ci` lists it with that command.
- `doc-ts-stats` turns TurboSnap on without a question when the build script passes `--stats-json`.
- `doc-ts-nosb` offers no TurboSnap fix where there's no Storybook main config.
- `doc-ts-vitest` turns TurboSnap on for Vitest only when `chromaticPlugin` sets `turboSnap: true`.
- `doc-release-age` adds `chromatic` at the newest version the package manager's minimum release age installs, then installs once.
- `doc-ver-latest` passes when the installed `chromatic` is the latest release.
- `doc-ver-minor` says how many minor versions behind the installed `chromatic` is, as a fixable info line.
- `doc-ver-major` warns when the installed `chromatic` is a major version behind, with each major's release notes.
- `doc-ver-offline` says it tried the npm registry and couldn't, and still finishes.
- `doc-ver-missing` says `chromatic` isn't installed when package.json lists it but nothing is installed.
- `doc-ver-pick` asks in a terminal which update to apply: Major, Minor, Patch or Nothing.
- `doc-ver-nothing` changes nothing when Nothing is picked.
- `doc-ver-yes` applies the minor or patch update with `--yes` and skips the major, with its release notes and `--apply` command.
- `doc-ver-ci` lists the major update, not the minor or patch, without a terminal, with its release notes and `--apply` command.
- `doc-apply-major` and `doc-apply-patch` apply one `chromatic.update:*` choice by its ID, and nothing else.
- `doc-pick-ci` needs `--project` at a monorepo root with several set-up projects and no terminal (exit `2`).
- `doc-pick-project` checks the one project `--project` names.
- `doc-pick-tty` asks which project to check in a terminal.
- `doc-above` fails a package whose Playwright, Cypress or Vitest config is at the repository root, and passes once `CHROMATIC_ARCHIVE_LOCATION` points at the archives, exported or in the project's `.env`.
- `doc-archive-file` fails a `CHROMATIC_ARCHIVE_LOCATION` that names a file, from the package or next to the config, while a folder that doesn't exist yet still passes; `doc-archive-symlink` passes the folder a `test-results` symlink points to.
- `doc-above-file` points to `init`, rather than stopping with `ENOTDIR`, when a folder above has a `.storybook` file, and `doc-storybook-file` does the same in the folder that has it.
- `doc-root-file` checks a set-up package from the repository root even though the root has a `.storybook` file, and `doc-root-named-file` checks the root instead when its build script names that file.
- `doc-build-dir-file` fails a `storybookBuildDir` that names a file, and doesn't say to build Storybook into it.
- `doc-project-file` stops with `No directory at <path>` when `--project` names a file, in doctor and in `init`.
- `doc-rebase-file` offers no `storybookConfigDir.rebase` onto a `.storybook` file, and `doc-base-dir-file` fails a `storybookBaseDir` that names a file.
- `doc-above-noproject` points a package with nothing to check at the folder above where its tests run.
- `doc-token-hint` repeats doctor's flags in its closing hint, without the project token.
- `doc-no-token` warns, without failing, when there's no project token.
- `doc-skills` ends a passing run outside CI with a pointer to Chromatic's agent skills.
- `doc-tty` renders the same report in a terminal.
- `doc-preview` builds Storybook with stats into a temporary folder and shows what preview reaches, how often those files changed, and which import reaches the most.
- `doc-preview-empty` builds Storybook with stats but shows no preview check and keeps no stats file when preview imports nothing.
- `doc-preview-fail` keeps reporting when that Storybook build fails, with an info line that points to `build-storybook.log`.
- `doc-preview-off` doesn't build when TurboSnap is off, and says how to make a stats file.
- `doc-preview-prebuilt` doesn't build for a prebuilt Storybook: it reads that build's stats file, or says how to make one.
- `doc-preview-pw` shows no preview check for Playwright, Cypress or Vitest.
- `doc-unseen` lists the project's stylesheets, images and fonts that are in neither the stats file's module graph nor `staticDirs`, with repository-root paths, as an info line that leaves the exit code alone.
- `doc-unseen-yes` skips the `externals` fix under `--yes`, because it asks whether Storybook reads those files.
- `doc-unseen-fix` adds them to `externals` in a terminal after a yes, and the check is gone afterwards.
- `doc-unseen-covered` leaves out files an `externals` or `untraced` glob already names.
- `doc-apply-unseen` adds them to `externals` without a terminal when `--apply externals.addUnseen` names the fix.
- `doc-apply-ids` shows each fixable item's ID, and only the fixes doctor can apply now.
- `doc-apply-unknown` exits `2` and writes nothing when a named ID isn't offered, and lists the IDs that are.
- `doc-apply-bare` exits `2` and writes nothing when an `--apply` names no ID, with or without `=`.
- `doc-apply-early` exits `2` and writes nothing when one named fix appears only after another named one is applied, and says to apply that one first.
- `doc-apply` applies one fix by its ID without a terminal, then lists the fixes it made available, each with its `--apply` command.
- `doc-apply-unlocked` applies one of those with the command doctor printed.

## How to get to it (user POV)

- Run `npx chromatic doctor` in a project, in a folder inside one, or at a monorepo's root.
- Add `--project <dir>` to pick the project, `--fix` to fix, `--yes` to fix without confirming, and `--apply <id>` to apply one fix by the ID the report shows.
- Pass any main-command option, such as `--config-file`, `--playwright` or `-t`. Doctor reads it the same way a build does.

## Driving it with control-chromatic

Preconditions:

- `$S doctor` exits 0. Doctor needs no Storybook stats and no backend.
- `CI=1` is set for every `$S run` journey except `doc-skills`, so the result doesn't depend on your shell. `$S run` pipes stdin, so doctor never prompts there.
- `CHROMATIC_PROJECT_TOKEN` is set to any value, such as `chpt_fake`, except in `doc-no-token`.
- The `doc-preview*` journeys need a Storybook that builds. Prepare one with `F=$($S e2e-fixture react-vite | tail -1)`, which needs the npm registry.
- `doc-release-age` needs the npm registry, and its pnpm variant needs `pnpm` on `PATH`. Preparing the `doc-preview*` fixture needs the registry too.
- The `doc-ver-*`, `doc-apply-major` and `doc-apply-patch` journeys need the npm registry and their own copy, `G=$($S e2e-fixture react-vite ver | tail -1)`, an npm project with TurboSnap off. Set `L=$(npm view chromatic version)`, the latest release.
- The `doc-unseen*` and `doc-apply-unseen` journeys need a monorepo Storybook that builds. Prepare one with `M=$($S e2e-fixture monorepo-npm unseen | tail -1)`, which needs the npm registry.
- Every other journey runs offline. Where package.json lists `chromatic`, that adds an info line about the installed version, which no summary counts.
- Each journey that commits does so in `$FIXTURE` or in a new git repository under `$WORK`, never in the checkout.

## Gotchas

- `$S run` and `$S tty` pass your environment through. A `CI` or `CHROMATIC_PROJECT_TOKEN` in your shell changes the token check, the skills pointer and whether doctor prompts. Set or unset them as each journey says.
- `$S tty` sends no keys. A run that prompts, such as `doc-pick-tty` or `doctor --fix` in a terminal, waits until `--timeout`, and the helper exits `2` with the pane saved. Answer with `tmux -L vcc-$RUN_ID-<label> send-keys`, and stop the session with `tmux -L vcc-$RUN_ID-<label> kill-server`. Don't use `$S cleanup` for that: it deletes `$WORK`, with `$FIXTURE` and every repository the later journeys use, so run it only after the last journey.
- A fix that adds `chromatic` runs a real install. Without network access it fails with `<pm> install failed`, exit `1`, and `package.json` keeps the edit. Add `chromatic` to `devDependencies` first in journeys that aren't about installing.
- The latest release moves. Read `$L` with `npm view chromatic version` when you run the `doc-ver-*` journeys, and work out `<N>` and `<K>` from it. `doc-ver-minor` needs `$L` to be an 18.x release after 18.10; once a new major ships, pin an earlier minor of that major instead. 16.10.1 and 16.9.1 are the newest 16.x and 16.9.x releases.
- Unlike the install, the latest-release lookup asks for the registry through the package manager found from the checked project's nearest `package.json` folder: Yarn with `yarn.lock`, npm with `package-lock.json`, and otherwise Yarn whenever `yarn` is installed, pnpm projects included. Yarn ignores `npm_config_registry`, so that variable takes the lookup offline only in an npm project such as `$G`, not in `$FIXTURE`.
- An update keeps how the range pins: an exact pin stays exact and `^` stays `^`. A minimum release age can hold each update target back, and the line says so.
- The release-age result depends on the date and on what's published. Work out `<V>` from `npm view chromatic time --json` when you run it. Don't copy a version from an earlier run.
- Doctor reads the package manager from the repository root's `packageManager` field or lockfile. Without either, it looks above the folder it checks, as the main command does, and finds any enclosing Yarn or pnpm project outside the fixture's repository, such as when `VERIFY_ROOT` is inside another checkout. Only then does it fall back to npm. Give every npm fixture that installs a `package-lock.json`. Yarn 4.15 and later refuse releases younger than a day by default, so a Yarn 4 fixture can hit the gate without any setting.
- Doctor reads `.storybook` only when the Storybook main config matches `main.<ext>`. An empty `.storybook` folder counts as a project for the no-project gate but fails `No Storybook found`.
- A folder with only `chromatic.config.json`, or only a script that runs `chromatic`, is set up, so doctor checks it and fails instead of stopping at the no-project gate.
- Run doctor only in `$FIXTURE` or a repository under `$WORK`. In the chromatic-cli checkout, it checks and offers to fix this repository's own Storybook.
- `$S doctor` is the helper's own health check. Every journey here drives `chromatic doctor` through `$S run … -- doctor` or `$S tty … -- doctor`.
- Every Storybook journey that starts with TurboSnap on builds Storybook first, such as `doc-pick-project`, `doc-token-hint`, `doc-no-token`, `doc-tty`, `doc-release-age` and `doc-skills`. In a fixture without Storybook installed, the build fails. That adds `■  Storybook build failed` (`▲` in a terminal) and an info line, writes `build-storybook.log` into the project folder, and leaves the exit code and summary unchanged: info lines aren't counted. Assert on the summary and exit code, and expect `?? build-storybook.log` in `git status` (`?? packages/b/build-storybook.log` in `$WORK/mono`). A run where `--fix` turns TurboSnap on, such as `doc-fix-yes` or `doc-ts-stats`, doesn't build: its `After fixes` section has `● No stats file to show what preview imports` instead, which says to run doctor again and names no build command.
- The `--apply` commands doctor prints carry `--project` relative to the folder doctor ran in (`.` in the project's own folder) and repeat doctor's other flags, such as `--skip-update-check`, but never `--fix`, `--yes` or the project token. Copy them from the output; don't build them by hand.
- `--apply` checks every named ID before it applies any fix, so a run with one ID doctor doesn't offer applies nothing, not even the IDs it does offer. With `--apply` but not `--yes`, doctor applies only the named fixes.
- Box details wrap at about 70 columns, and clack lines put two spaces after the marker (`◇  Building…`). Match quoted lines with whitespace and `│` collapsed, not with a literal `grep -F`. `(fixable:` is followed by a no-break space (U+00A0), which `tr -s ' '` and `[[:space:]]` leave alone, so turn it into a space first, as in `sed 's/\xc2\xa0/ /g'`.
- A preview check is `▲` when a commit in the last 90 days changed a project file behind preview, `●` (info) when git can't tell, and `✔` otherwise. It never fails doctor and never offers a fix. A preview that imports nothing has no preview check.
- `init` runs doctor's checks at the end, but never the preview check or its Storybook build.
- The `outside the module graph` check needs the stats file the preview check builds or reads. Where there's none, such as with TurboSnap off, doctor shows the missing-stats line instead of it.
- `externals` matches from the repository root, so a path relative to `packages/ui`, such as `src/_tokens.scss`, matches nothing and leaves the file listed.
- It lists untracked files too, so files another journey left in the project show up. Restore the fixture between journeys.
