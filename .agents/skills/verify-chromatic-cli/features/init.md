# Init

`chromatic init` sets up Chromatic in a repository, step by step, the way `storybook init` does. It finds the Storybook or the Playwright, Cypress or Vitest tests, gets the project token and checks it with the index, writes `chromatic.config.json`, adds `chromatic` and a `chromatic` script to `package.json`, installs once, adds Chromatic's log files to `.gitignore`, and ends by running doctor's checks. It writes nothing when it can't set up the project where it is: no git repository, nothing to set up, a project whose tests or Storybook run from a folder above, a folder with no `package.json`, or a framework with no config. It exits `0` when set up, and `1` when it stops or a check fails afterwards. It never reads or writes CI files.

## Sub-features

- `init-help` prints init's own `--help`, not the package description.
- `init-storybook` sets up a Storybook project without a terminal and runs the checks.
- `init-dry-run` says what it would write and writes nothing.
- `init-no-token` warns and continues without a token.
- `init-bad-token` stops when the index rejects the token, before writing anything.
- `init-nothing` stops in a repository with no Storybook or test setup.
- `init-no-git` stops outside a git repository.
- `init-pick-ci` needs `--project` at a monorepo root with several setups and no terminal.
- `init-pick-here` sets up the project init runs inside, with `storybookBaseDir` and the framework's package.
- `init-pick-project` sets up the project `--project` names.
- `init-sb-none` stops when `--framework storybook` names a folder with no Storybook main config.
- `init-above` stops when the framework's config is in a folder above the project, and points there.
- `init-no-package` stops when the project folder has no `package.json`.
- `init-no-config` stops when the framework `--framework` names has no config here or above.
- `init-existing` edits an existing config file in place, and a second run changes nothing.
- `init-install` installs once, at the newest version the package manager's minimum release age allows.
- `init-skills` ends a run outside CI with a pointer to Chromatic's agent skills.
- `init-tty` asks for the token and confirms each edit in a terminal.
- `init-tty-flag` offers to save a `--project-token` token to `.env` in a terminal, and never without one.

## How to get to it (user POV)

- Run `npx chromatic init` in a repository, at its root or inside a package.
- Add `--project <dir>` to pick the package, `--framework <name>` (`storybook`, `playwright`, `cypress`, `vitest`) when detection is wrong, `-t <token>` or `CHROMATIC_PROJECT_TOKEN` for the token, `--skip-install`, `--dry-run`, and `--yes` to accept every default.

## Driving it with control-chromatic

Preconditions:

- `$S doctor` exits 0. Init needs no Storybook stats.
- `CI=1` is set for every `$S run` journey except `init-skills`, so the result doesn't depend on your shell. `$S run` pipes stdin, so init never prompts there.
- `CHROMATIC_PROJECT_TOKEN=chpt_fake` and `CHROMATIC_INDEX_URL=http://127.0.0.1:9` are exported, so init can't reach the index and continues unchecked (`◇ Couldn't reach Chromatic to check the token; continuing`). `init-bad-token` needs the real index instead, and `init-install` needs the npm registry. Every other journey runs offline.
- "A Storybook fixture" means: run `$S fixture`, write `export default {};` to `$FIXTURE/.storybook/main.js`, set the `build-storybook` script to `storybook build`, add `"devDependencies": {"storybook": "^9.0.0"}`, and commit.
- Each journey that commits does so in `$FIXTURE` or in a new git repository under `$WORK`, never in the checkout. Every `git status`, `git diff`, `git checkout` and `git clean` below runs as `git -C <the journey's repository>`, never in the chromatic-cli checkout.

- **Help.** Run `$S fixture`, then `$S run init-help --cwd "$FIXTURE" -- init --help`. Exit code `0`. The first line is `Set up Chromatic in your project, step by step`, followed by `$ chromatic init [options]` and the `--project`, `--framework`, `--project-token`, `--skip-install`, `--dry-run` and `--yes` options.
- **Storybook project.** On a Storybook fixture, run `$S run init-storybook --cwd "$FIXTURE" -- init --yes --skip-install`. Exit code `0`. stdout has, in order: `● Found the repository root · Storybook 9.0`, `● Using CHROMATIC_PROJECT_TOKEN (ends in …fake).`, `◆ Wrote chromatic.config.json`, `◆ Added chromatic and a "chromatic" script to package.json`, `● Skipped installing. Run npm install later.`, `◆ Added build-storybook.log, chromatic.log, chromatic-build-*.xml, chromatic-diagnostics.json to .gitignore`, `◇ Checked the setup: …`, and `└ Chromatic is set up.` with `Run npm run chromatic to create your first baselines.` `git status --short` lists `M package.json`, `?? .gitignore` and `?? chromatic.config.json`. `chromatic.config.json` holds only `"$schema"`. `package.json` gains `"chromatic": "chromatic"` in `scripts` and `chromatic` at the CLI's version in `devDependencies`. The TurboSnap fix is skipped with the question about `preview-stats.json`, as in doctor's `doc-ts-question`.
- **Dry run.** On a fresh Storybook fixture, run `$S run init-dry-run --cwd "$FIXTURE" -- init --yes --dry-run`. Exit code `0`. stdout has `init · setting up Chromatic (dry run: nothing will be written)`, `◆ Would write chromatic.config.json`, `◆ Would add chromatic and a "chromatic" script to package.json`, `● Skipped the setup check in a dry run.` and `└ Dry run finished. Nothing was written.` `git status --short` is empty.
- **No token.** On a fresh Storybook fixture, run `env -u CHROMATIC_PROJECT_TOKEN $S run init-no-token --cwd "$FIXTURE" -- init --yes --skip-install`. Exit code `0`. stdout has `▲ No project token. Set CHROMATIC_PROJECT_TOKEN before running Chromatic.`, then writes the same files as `init-storybook`.
- **Token the index rejects.** On a fresh Storybook fixture, run `env CHROMATIC_INDEX_URL=https://index.chromatic.com $S run init-bad-token --cwd "$FIXTURE" -- init --yes --skip-install`. Exit code `1`. stdout has `Chromatic doesn't know this token. Check it on your project's Manage page.`, and stderr is `Error: Invalid project token`. `git status --short` is empty.
- **Nothing to set up.** Run `$S fixture`, then `$S run init-nothing --cwd "$FIXTURE" -- init --yes --skip-install`. Exit code `1`. stdout has `■ No Storybook, Playwright, Cypress or Vitest setup found in this repository.` and `Set up Storybook first with npm create storybook@latest, then run this again.`; stderr is `Error: Nothing to set up`. `git status --short` is empty.
- **No git.** In a folder under `$WORK` with a `package.json` and `.storybook/main.js` but no git repository, run `$S run init-no-git --cwd "$WORK/nogit" -- init --yes --skip-install`. Exit code `1`. stdout has `■ This folder is not in a git repository. Chromatic uses git history to pick baselines.`; stderr is `Error: Not a git repository`. No file is written.
- **Monorepo without a terminal.** Create a git repository `$WORK/mono` with a root `package.json` (`"workspaces": ["packages/*"]`), `packages/a` with `"build-storybook": "storybook build"` and `.storybook/main.js`, and `packages/b` with only a name and a `playwright.config.ts`. Commit. Run `$S run init-pick-ci --cwd "$WORK/mono" -- init --yes --skip-install`. Exit code `1`. stdout has `■ Found 2 test setups:` with `packages/a · Storybook` and `packages/b · Playwright tests`, and `Pick one with --project <dir>, or run init from inside it.`; stderr is `Error: More than one project to set up`. `git status --short` is empty.
- **Inside a package.** Run `$S run init-pick-here --cwd "$WORK/mono/packages/b" -- init --yes --skip-install`. Exit code `0`. stdout has `● Found 2 test setups; using packages/b · Playwright tests, where init ran` and `◆ Wrote chromatic.config.json ("playwright": true, "storybookBaseDir": "packages/b")`. `packages/b/package.json` gains `chromatic` and `@chromatic-com/playwright` in `devDependencies` and a `chromatic` script, and the root `.gitignore` is created. Restore with `git -C "$WORK/mono" checkout . && git -C "$WORK/mono" clean -fd`.
- **Pick with `--project`.** Run `$S run init-pick-project --cwd "$WORK/mono" -- init --yes --skip-install --project packages/a`. Exit code `0`. stdout has `● Found packages/a · Storybook` and `◆ Wrote packages/a/chromatic.config.json ("storybookBaseDir": "packages/a")`. Restore the same way.
- **`--framework storybook` with no Storybook.** Run `$S run init-sb-none --cwd "$WORK/mono" -- init --yes --skip-install --project packages/b --framework storybook`. Exit code `1`. stdout has `■ No Storybook found in packages/b.` and `Set up Storybook first with npm create storybook@latest, then run this again.`; stderr is `Error: No Storybook`. `git status --short` is empty. The same happens for a package with no `.storybook` at all and for one with a `.storybook` that has no `main.*`. When a `.storybook/main.*` exists at the repository root instead, stdout has `■ Storybook builds from the repository root (.storybook), so Chromatic has to run there to find the Storybook.` and stderr `Error: Nothing to set up in packages/b`. A Storybook main config in any script's `-c` folder counts, even with an absolute path: give `packages/b` a `sb/main.js` and a script `"build:sb": "storybook build -c <absolute path of packages/b/sb>"`, commit, and the same command (label `init-sb-custom`) exits `0` and writes `packages/b/chromatic.config.json`. Restore with `git -C "$WORK/mono" reset -q --hard HEAD~1 && git -C "$WORK/mono" clean -fd`.
- **Tests that run from above.** Create a git repository `$WORK/root-pw` with a root `package.json` (`"workspaces": ["packages/*"]`) and `playwright.config.ts`, `packages/app/package.json` with only a name, and `packages/web/package.json` with `packages/web/tests/vitest.config.ts`. Commit. `git status --short` stays empty after each of these:
  - `$S run init-above --cwd "$WORK/root-pw" -- init --yes --skip-install --project packages/app --framework playwright`. Exit code `1`. stdout has `■ Playwright runs from the repository root (playwright.config.ts), so Chromatic has to run there to find its archives.` and `● Run npx chromatic init to set it up there.`; stderr is `Error: Nothing to set up in packages/app`.
  - `$S run init-no-package --cwd "$WORK/root-pw" -- init --yes --skip-install --project packages/web/tests`. Exit code `1`. stdout has `■ packages/web/tests has no package.json, so init has nowhere to add chromatic and a "chromatic" script.` and `Add a package.json to packages/web/tests, or move the Vitest config to packages/web, the nearest package, and update the paths in it, then run this again.`
  - `$S run init-no-config --cwd "$WORK/root-pw" -- init --yes --skip-install --project packages/app --framework cypress`. Exit code `1`. stdout has `■ No Cypress config found in packages/app or above.` and `Set up Cypress with Chromatic first (https://www.chromatic.com/docs/cypress/), then run this again.`; stderr is `Error: No Cypress config`.
- **Existing config.** On a fresh Storybook fixture, write `{"onlyChanged":true}` to `chromatic.config.json` and commit. Run `$S run init-existing --cwd "$FIXTURE" -- init --skip-install`. Exit code `0`. stdout has `◆ Updated chromatic.config.json` and `◇ Checked the setup: 8 passed`. The file keeps `"onlyChanged": true` and gains `"$schema"`. Run again with `--yes` (label `init-existing-yes`): `◆ chromatic.config.json already has what Chromatic needs` and `◆ package.json already has chromatic and a script that runs it ("chromatic")`, and no file changes from the first run.
- **Install under a release age.** On a fresh Storybook fixture, write `before=<date>` to `.npmrc`, picking a date between two `chromatic` releases from `npm view chromatic time --json`, and commit. Run `$S run init-install --cwd "$FIXTURE" -- init --yes`. Exit code `0`. stdout shows `Installing with npm`, then `◇ Installed with npm`, once. `jq -c .devDependencies package.json` has `"chromatic": "^<V>"`, where `<V>` is the newest stable release before that date and no newer than the CLI, and `node_modules/chromatic/package.json` has version `<V>`.
- **Skills pointer.** On a fresh Storybook fixture, run `env -u CI $S run init-skills --cwd "$FIXTURE" -- init --yes --skip-install`. Exit code `0`. The outro ends with `Using an AI agent? Give it Chromatic's skills: https://www.chromatic.com/docs/skills/`. With `CI=1`, as in `init-storybook`, the line is absent.
- **TTY.** On a fresh Storybook fixture, run `env -u CI $S tty init-tty --cwd "$FIXTURE" --timeout 10 -- init --skip-install`. The helper times out (exit `2`) at the prompt, and `pane.txt` shows `● Find your project token on your project's Manage page: https://www.chromatic.com/start` and `◆ Paste your project token, or press Enter to use CHROMATIC_PROJECT_TOKEN (ends in …fake)`. Answer with `tmux -L vcc-$RUN_ID-init-tty send-keys Enter`, then read it with `tmux -L vcc-$RUN_ID-init-tty capture-pane -p -S -`: init shows the `package.json` diff and asks `◆ Add chromatic and a "chromatic" script to package.json?`. Keep answering with `send-keys`. After the last answer, wait for the pane to show `__VERIFY_EXIT=<code>`, since the checks take a few seconds: `for i in $(seq 60); do tmux -L vcc-$RUN_ID-init-tty capture-pane -p -S - | grep -q '__VERIFY_EXIT=' && break; sleep 1; done`. Then save it with `tmux -L vcc-$RUN_ID-init-tty capture-pane -p -S - > "$EVIDENCE/init-tty/pane-final.txt"`; the helper wrote no `exit_code` for this run. Stop the session with `tmux -L vcc-$RUN_ID-init-tty kill-server`. The token came from the environment, so `pane-final.txt` has no `Save it in a gitignored .env for local runs?` and there's no `.env`.
- **Flag token in a terminal.** On a fresh Storybook fixture, run `env -u CI -u CHROMATIC_PROJECT_TOKEN $S tty init-tty-flag --cwd "$FIXTURE" --timeout 10 -- init --skip-install --project-token chpt_flag`. The helper times out (exit `2`), and `pane.txt` shows `● Using the project token from --project-token.` and `◆ Save it in a gitignored .env for local runs?` with `● Yes`. Press Enter with `tmux -L vcc-$RUN_ID-init-tty-flag send-keys Enter`, keep answering Enter, then wait for `__VERIFY_EXIT=`, save `pane-final.txt` and kill the server as in `init-tty`. `pane-final.txt` has `◆ Saved the token to .env (gitignored, never committed)` and `__VERIFY_EXIT=0`. `.env` is `CHROMATIC_PROJECT_TOKEN=chpt_flag`, and `git -C "$FIXTURE" check-ignore .env` prints `.env`. Controls, each on a fresh Storybook fixture: answering No (`send-keys Right Enter` at that question) writes no `.env`; `env -u CHROMATIC_PROJECT_TOKEN $S run init-flag-ci --cwd "$FIXTURE" -- init --yes --skip-install --project-token chpt_flag`, with `CI=1` and no terminal, exits `0` without the question and writes no `.env`.
- **Proof.** Each label dir holds the command, both streams and the exit code. For journeys that write, also save `git status --short`, `git diff` and the written files into the label dir. For journeys that stop, save the empty `git status --short`.

## Gotchas

- `$S run` and `$S tty` pass your environment through. A `CI`, `CHROMATIC_PROJECT_TOKEN` or `CHROMATIC_INDEX_URL` in your shell changes the token step, the skills pointer and whether init prompts. Set or unset them as each journey says.
- With the real index and a real project token, init checks the token for real. Use the unreachable `CHROMATIC_INDEX_URL` everywhere except `init-bad-token`, which uses a fake token that the index rejects.
- Without `--skip-install`, init runs a real install, which needs the registry. Use `--skip-install` in journeys that aren't about installing.
- The release-age result depends on the date and on what's published. Work out `<V>` from `npm view chromatic time --json` when you run it.
- Init reads the package manager from the lockfile, and uses npm without one. Yarn 4.15 and later refuse releases younger than a day by default.
- Without a terminal, init applies edits to existing files without asking. In a terminal, it shows each diff and asks first.
- `$S tty` sends no keys, so every prompt waits until `--timeout`. Answer with `tmux -L vcc-$RUN_ID-<label> send-keys`, and stop the session with `tmux -L vcc-$RUN_ID-<label> kill-server`. Don't use `$S cleanup` for that: it deletes `$WORK`, with `$FIXTURE` and every repository the later journeys use, so run it only after the last journey.
- Never run init in the chromatic-cli checkout. It would set up this repository's own Storybook.
